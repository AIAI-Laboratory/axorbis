# Desktop app

Tauri loads the React UI from `web/` and starts `integration/review_runner.py` through `src-tauri/src/commands.rs`. The runner uses SynthScholar 0.0.11 search and full text clients for a Computer Science literature map. See the [root README](../README.md) for installation, supported sources, evidence rules and output files.

From the repository root, run `npm run desktop:dev`. The start form accepts a topic, optional required and related concepts, and a result limit. The run view shows nine explicit stages: query planning, search/deduplication, scope screening, source enrichment, evidence mapping, study profiling, cross-paper analysis, candidate-gap detection, and targeted gap verification. The last stage is skipped only when candidate-gap detection explicitly found none. Result views separate strict core papers from background studies, display `YES/NO/UNKNOWN/NOT_APPLICABLE` matrix values, grounded paper claims, relational cross-paper findings, gap-local coverage, counter-evidence, scoped counter-searches, query provenance, and diagnostics. Legacy review folders remain readable through compatibility fields.

Keys are never stored in the review folder or browser storage. Provider keys, selected Gemini keys, and the optional Typesafe Jev AI key are passed to Python through stdin. A Gemini key is required for concept profiling and evidence selection from exact saved candidate spans. Scope screening defaults to Gemini; the new Jev mode can be toggled in the start form after configuring `TYPESAFE_API_KEY` in Settings. Jev classifies every retrieved and counter-search paper, and retrieved full text is used to reassess eligible papers without Gemini overriding Jev scope decisions. No regex paper-classification fallback is used. OpenAlex can use a key when configured. Rerunning creates a new output folder and repeats acquisition.

Gemini scope screening uses a strict JSON score schema (`100` explicit yes, `50` unknown, `0` explicit no). The per-review `gemini-calls.jsonl` audit file records complete Gemini request bodies and raw response bodies, including malformed responses, but omits Authorization headers and redacts configured API keys. It is available from the progress view and output folder; prompts may contain paper text.
