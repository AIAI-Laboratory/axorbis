# Desktop app

Tauri loads the React UI from `web/` and starts `integration/review_runner.py` through `src-tauri/src/commands.rs`. The runner uses SynthScholar 0.0.11 search and full text clients for a Computer Science literature map. See the [root README](../README.md) for installation, supported sources, evidence rules and output files.

At startup the desktop verifies the review runtime once. If SynthScholar is unavailable, development installs it into the checkout's `.venv`; packaged builds install it into `~/.axorbis/runtime/.venv` from the bundled setup and requirements files. On macOS, a missing compatible interpreter is replaced by a pinned, SHA-256-verified Python 3.11 standalone runtime under `~/.axorbis/runtime/python`, so no system Python or Homebrew installation is required. `SYNTHSCHOLAR_PYTHON` remains an explicit interpreter override.

The reference graph checks every selected paper for Crossref and OpenAlex references by DOI or matched title, merges their cited works, then tries Semantic Scholar by DOI, arXiv ID, or exact title when both sources have none. Up to four papers are looked up concurrently, while individual source failures are kept separate and results stay in review order. It fills missing paper metadata from public OpenReview v2 notes matched by note ID or exact title, with OpenReview/PDF links when available. Cited works are linked to their source paper and duplicates are merged by DOI or normalized title. By default papers are spaced into two rings and the graph shows up to eight prominent references shared by multiple papers with subdued links. A single click selects a paper and shows its details without changing the graph; the detail panel previews five cited works and opens the full, scrollable list in a modal. Double-clicking opens a centered subgraph of only that paper and the works it cites. Other review papers disappear from the subgraph canvas, while the sidebar remains available. Closing its detail returns to the overview, while “Xem tất cả” shows the complete graph. Paper and reference labels show available author and year; references without authors show a shortened title, with overlapping labels revealed on hover or selection. The graph shows coverage and per-paper lookup failures; papers without indexed references remain unlinked. Complete results are cached in `citation-graph.json` and can be refreshed from the graph view.

The standalone DOI/title lookup is no longer part of the desktop sidebar. The reference graph inside completed review results remains available.

From the repository root, run `npm run desktop:dev`. The start form accepts a topic, optional required and related concepts, inclusion/exclusion rules, dates, language, publication type, search sources, extraction dimensions, a synthesis objective, a screening template, an audit mode, source-text retention, and a result limit. The run view shows nine explicit stages: query planning, search/deduplication, scope screening, source enrichment, evidence mapping, study profiling, cross-paper analysis, candidate-gap detection, and targeted gap verification. The last stage is skipped only when candidate-gap detection explicitly found none. Result views separate strict core papers from background studies, display `YES/NO/UNKNOWN/NOT_APPLICABLE` matrix values, grounded paper claims, claim-type-specific cross-paper findings, topic-relative direction coverage, maturity labels, emerging or sparse areas, underexplored intersections, gap-local coverage, counter-evidence, scoped counter-searches, query provenance, and diagnostics. Sparse areas are not automatically promoted to gaps, and bounded counter-search findings appear separately from candidate assessments. Legacy review folders remain readable through compatibility fields.

For a macOS drag-to-install image, run `npm run desktop:build:dmg` from the repository root. The verified artifact is under `src-tauri/target/release/bundle/dmg/` relative to this directory and contains `Axorbis.app` plus the `/Applications` drag target. Local builds are ad-hoc signed unless `APPLE_SIGNING_IDENTITY` is set; public release still requires Apple notarization. Never distribute the intermediate `rw.*.dmg` files under `src-tauri/target/release/bundle/macos/`.

For the Windows x64 NSIS installer, run `npm run desktop:build:exe` from the repository root. Its `*-setup.exe` output is under `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`. Native Windows builds use MSVC; macOS cross-builds require NSIS, LLVM/LLD, the Windows Rust target, and `cargo-xwin`.

Keys are never stored in the review folder or browser storage. Provider keys, selected Gemini keys, and the optional Typesafe Jev AI key are passed to Python through stdin. A Gemini key is required for concept profiling and evidence selection from exact saved candidate spans. Scope screening defaults to Gemini; Jev mode can be toggled in the start form after configuring `TYPESAFE_API_KEY` in Settings. Jev classifies every retrieved and counter-search paper, and retrieved full text is used to reassess eligible papers without Gemini overriding Jev scope decisions. No regex paper-classification fallback is used. OpenAlex can use a key when configured. Continuing an interrupted run creates a new output folder and reuses matching query, full-text, screening and evidence artifacts where available; rerunning a completed review starts fresh.

Gemini scope screening uses a strict JSON score schema (`100` explicit yes, `50` unknown, `0` explicit no). The per-review `gemini-calls.jsonl` audit file defaults to metadata and content hashes. The form can select full request/response bodies or disable audit entries. Authorization headers are omitted and configured API keys are redacted. It is available from the progress view and output folder; prompts may contain paper text.

New general reviews screen against the protocol question and eligibility rules; the temporal knowledge-graph criteria remain an explicit specialized template. Results now expose search completeness, unresolved screening, sensitivity to background records, reporting-only study-quality profiles, and bounded counter-search findings. Up to three candidate gaps are checked. `run-manifest.json` and `runtime-manifest.json` record version metadata, `execution-state.json` carries mutable run state, and editing a saved question writes a separate next-run draft rather than changing its original protocol. The desktop monitor uses structured stage events when present.

Optional one-hop citation snowballing expands the scientific corpus before screening, using Semantic Scholar backward and forward citations from up to five seed papers. This is separate from the exploratory reference graph shown after review. Start and end dates can be typed or selected from the native calendar; protocol values are saved as `YYYY-MM-DD`, while current source metadata permits year-level screening only.

The Methodology tab lets a reviewer adjudicate uncertain background records after a run. This rebuilds outputs from saved evidence without another model call; newly created gap candidates remain unverified until a separate counter-search. Gemini analyzes all available sentence candidates in bounded windows with neighboring context, while full-text parsing is capped at 100,000 characters per paper.
